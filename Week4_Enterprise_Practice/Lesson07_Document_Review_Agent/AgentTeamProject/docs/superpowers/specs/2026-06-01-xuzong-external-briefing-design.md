# 许总对外汇报材料重写设计

## 背景

许总提出：“志辉和廖总，对近期工作做个总结，我再把资料融入到我的汇报资料中。”后续确认该汇报面向甲方客户或外部合作方水利部，口径应以稳健汇报为主，同时保留技术备查材料。

当前已有初稿偏技术团队复盘，虽然包含提交记录、技术验证会纪要、链路风险和遗留事项，但不完全适合许总直接融入对外汇报材料。需要重构为“主文一页 + 附件备查”的材料形态。

## 目标

产出一份许总可以直接复用的对外汇报材料：

1. 主文采用稳健汇报型，强调已开展、已验证、下一步试点，不暴露过多内部工程问题。
2. 附件按许总要求的五项展开：工作内容和思路、技术体系、重点难点分析、成果实用性评估、心得体会与建议。
3. 事实依据来自已签合同要求、上周五技术验证会纪要、当前项目文档和近期提交记录。
4. 写作上采用自然中文和领导汇报口吻，避免明显 AI 腔、技术堆砌和内部缺陷暴露。

## 受众与口径

主受众是水利部或外部合作方。材料要服务许总对外表达，核心不是展示技术团队做了多少代码，而是说明地拓已围绕水土保持数智化升级开展 AI 辅助审查关键链路验证，并具备继续开展试点验证的基础。

主文应避免以下说法：

- 已完成完整生产系统。
- 已覆盖全部水保审查规则。
- 已能在原 PDF 上精准高亮全部证据。
- 已完成人员赋能和 AI 前沿信息收集全部合同内容。
- 当前问题都是系统缺陷或项目风险。

主文应采用以下说法：

- 已开展关键链路验证。
- 已形成初步 Demo 和技术验证基础。
- 下一步聚焦典型规则、典型样本和评效指标。
- 通过专家参与、样本验证和规则拆解持续提升实用性。

## 主文设计

主文控制在一页左右，结构不机械套用许总五个标题，而是采用对外汇报结构。

### 1. 工作定位

表达为：围绕水土保持数智化升级，近期已先行开展方案审查类 AI 辅助能力验证，重点探索大模型、智能体、文档解析和证据回链在水土保持方案审查中的应用路径。

核心边界：不是宣称“已经做成完整系统”，而是“开展关键链路验证”。

### 2. 已开展工作

写三类工作：

- 文档解析与结构化：PDF、附件、表格、附图等材料解析。
- 证据检索与规则匹配：围绕审查规则召回正文、表格、附件中的依据。
- 审查结果回链：输出审查问题、判断建议和对应原文依据。

### 3. 初步验证进展

稳健表述为：已形成初步 Demo，能够支持 PDF 解析、章节/页面定位、部分审查问题召回、审查意见生成和证据关联展示。

应强调“已具备继续开展试点验证的基础”，不写成“已经全面可用”。

### 4. 下一步试点安排

写会议确定的两条规则：

- 正文项目概况与附件批复一致性。
- 土石方平衡与借弃方来源去向。

写“基于 3 份测试 PDF 开展验证”。如果文件名未确认，不写具体名称。

### 5. 协同支持方向

表达为：后续希望结合典型项目材料、业务专家审查经验和实际工作流程，持续完善规则拆解、证据召回、专家复核和评效指标。

该段用于自然引出水利部或外部合作方提供样本、场景、专家口径和试点支持的价值。

## 附件设计

附件作为许总被追问时的备查材料，可比主文更技术，但仍然避免内部缺陷复盘式表达。附件按许总原始五项要求组织。

### 1. 工作内容和思路

说明当前不是铺完整产品，而是验证关键链路：

`PDF/附件/附图解析 -> 文本与表格入库 -> RAG 检索召回 -> 审查规则匹配 -> 大模型/智能体判断 -> 可回链审查结果`

强调先用两条典型规则验证，不急于铺开完整规则库。

### 2. 技术体系

按六层压缩表达：

- 文档解析层：MinerU/MMU 类工具解析 PDF、表格、附件。
- 数据入库层：结构化文本、表格、页面、bbox 元数据入库。
- 检索召回层：关键词检索 + 向量检索 + 重排。
- 规则判断层：规则拆解、证据槽、公式校验、大模型判断。
- 结果回链层：审查结论关联原文页码、片段和证据。
- 人工复核层：专家确认、修正、沉淀反馈。

### 3. 重点难点分析

对外稳健表达为“需要重点验证的问题”：

- 长文档解析准确性。
- 表格、附件、附图等多源材料的结构化。
- 审查证据的召回完整性。
- 审查规则从经验语言到可执行规则的拆解。
- 智能体是否能主动补充检索、调用工具和校验证据。

### 4. 成果实用性评估

表达为“当前成果具备试点验证价值”：

- 已能支撑关键链路 Demo。
- 已能对部分审查问题形成证据化输出。
- 已适合进入指定样本文档试点验证。
- 后续实用性通过解析耗时、召回命中、人工确认有效率、证据可定位率等指标评估。

### 5. 心得体会与建议

重点表达：

- AI 审查不是替代专家，而是提升材料定位、证据召回和初筛效率。
- 第一阶段应以典型规则和典型材料验证为主。
- 建议水利行业后续建立“规则库 + 样本库 + 专家反馈 + 评效指标”的协同机制。
- 附图深度识别、多模态审查、完整规则库、国产化部署可分阶段推进。

### 6. 阶段性待验证清单

列出近期可交付闭环：

- 使用 3 份测试 PDF 形成验证记录。
- 跑通 2 条典型规则。
- 建立召回评测表。
- 记录解析、检索、单规则判断耗时。
- 整理专家反馈和下一步规则扩展建议。

## 写作约束

用户要求后续结合 `/humanizer-zh` skill 写作。当前可用技能列表中没有 `humanizer-zh`，因此本设计把它转化为写作约束：

- 用自然中文，不写明显 AI 腔。
- 少用抽象套话，避免连续堆叠“赋能、闭环、生态、底座”等词。
- 句子尽量短，适合领导汇报材料直接复用。
- 技术名词保留必要项，但每个技术点都要服务业务价值。
- 主文少暴露内部问题，附件将风险表达为“待验证事项”和“下一步完善方向”。

## 验收标准

最终材料应满足：

1. 许总可直接将主文融入对水利部或外部合作方的汇报材料。
2. 主文一页左右，稳健、克制、有进展、有下一步。
3. 附件完整覆盖许总要求的五项，并保留技术验证事实。
4. 不夸大成果，不把原型描述成生产系统。
5. 不遗漏 2 条典型规则、3 份测试 PDF、6 月 4 日节点和“解析准确、入库干净、召回完整、证据可定位”四个阶段重点。
6. 写作口吻自然，不像内部技术日报或 AI 生成说明。

## 后续实施边界

本设计只规定材料重写方向。正式改稿时应基于现有 `docs/许总近期工作总结初稿-2026-06-01.md`，可以另存为对外汇报版本，避免覆盖已有技术复盘材料。
